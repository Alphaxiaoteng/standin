# StandIn · Demo 视频逐镜脚本

> 用途：Monad Metropolis 黑客松 Track 04 提交视频。逐镜执行，旁白为**真人中文口播**逐字稿。
> 本脚本所有画面、按钮、字段、金额、合约地址均对应仓库中真实存在的页面/代码，不含编造。

## 0. 录制规格与纪律（违反即废，先读这段）

| 项 | 硬性要求 |
|---|---|
| 总时长 | **3:08**（落在比赛允许的 2:45–3:15；系统对 <2:00 或 >4:00 自动拒收） |
| 解说方式 | **真人中文解说，全程口播**。**严禁任何 AI 合成语音 / TTS / 变声**。宁可声音有停顿、有呼吸、有轻微口误，也不要机器音。 |
| 人声必现 | **严禁「纯背景乐 + 字幕、无人声」**。每一段都必须有真人声音覆盖。背景乐（可选）压到人声的 15% 以下，不得盖过解说。 |
| 播放速率 | **严禁倍速 / 快进 / 抽帧**。所有等待（数据真实采集、门禁裁决）用**硬跳切**衔接，而不是加速播放。 |
| 分辨率 | **≥720p**，建议 1080p / 60fps；16:9 横屏；屏幕录制，浏览器整屏（隐藏书签栏与个人头像/账号信息）。 |
| 语速基准 | 中文解说约 **4 字/秒**。每镜旁白后标注 `字数≈`，用于自检时长，超字就删词，不要靠语速硬塞。 |
| 环境预置 | 提前 `pnpm dev`，浏览器停在首页；`.data/ledger.json` 已有既往真实记录（本金余额、门禁避免损失、拦截/放行流水）。演示现场会真实写入账本。 |
| 数据诚实 | 页面显示的亏损单、避免损失金额都是真实推导，**不得后期 P 图改数**。改了就前功尽弃。 |

## 1. 逐镜脚本

### 镜头 1 · 0:00–0:20（20s）直接进入拦截，不讲行业痛点
- **画面**：`/guardrail`「门禁红绿灯」页。左右两栏并排：左「红灯 · 拦截」、右「绿灯 · 放行」，两栏此刻均为空态。鼠标**不做任何铺垫介绍**，直接落到左栏第一个按钮「▶ 收款方篡改」并点击。稍等约 1 秒，左栏刷出红色 `INTERCEPTED` 结果。
- **屏幕动线**：`/guardrail` → 点「▶ 收款方篡改」（`RED_SCENARIOS` 第一项）→ 左栏出现：绿色数字「避免损失（按声明意图金额）0.50 USDC」→ 下方逐字段比对表中「收款方」一行标红、带红色徽章「收款方被篡改」→ 底部红徽章「1 项不一致」+ 拦截依据 `Recipient mismatch`。
- **旁白**（字数≈78）：
  > 直接看拦截。这是一个 AI Agent 正要向「已授权数据商户」转 0.5 USDC 的瞬间。被提示词注入劫持后，它实际要转给了一个陌生攻击者地址。门禁当场比对声明意图和真实 calldata，收款方这一字段对不上——红色，已拦截，这 0.5 USDC 一分没出去。
- **要点**：前 20 秒必须是「拦截动作」本身，**禁止**出现市场规模、赛道介绍、团队自拍。评委异步初筛平均只停留 90–120 秒，开场即高潮。

### 镜头 2 · 0:20–0:45（25s）红绿灯并排对比（安全项目唯一自证）
- **画面**：同一页保持左红不消失，右栏点「▶ 运行「正常采购」」刷出绿色；再点左栏第二个按钮「▶ 无限授权」把红灯刷新为更高危的裁决。最终定格：**左红（无限授权 · 已拦截）与右绿（正常采购 · 已放行）并排**。
- **屏幕动线**：右栏点「▶ 运行「正常采购」」→ 右栏出现绿色 `EXECUTED`、「按声明意图放款 0.50 USDC」、「全部一致」绿徽章 → 回到左栏点「▶ 无限授权」→ 左栏 `INTERCEPTED`、避免损失 **1.00 USDC**、「金额」行标红、箭头 `≠`、带「无限授权」徽章，底部「命中风险项」显红「1 项不一致」。
- **旁白**（字数≈98）：
  > 安全类项目，红绿灯并排是唯一能自证的方式。右边是合规调用：声明和 calldata 逐字段一致，门禁照意图放行，绿灯。左边换个更狠的：Agent 本只想授权 1.0 USDC 做流式支付，钓鱼合约却诱导它签 2 的 256 次方减 1 的无限授权——就「金额」一个字段对不上，也足够拒绝。同一条比对逻辑，绿的过、红的拦，这就是它的裁决边界。
- **要点**：这一镜务必让**红色避免损失金额**与**逐字段不一致证据**、**绿色全部一致**同框出现，画面停留≥3 秒供评委阅读。

### 镜头 3 · 0:45–1:10（25s）本金保护账本 + 留痕核验
- **画面**：切到 `/intercepts`「本金保护」。顶部「累计避免损失」为全账本累计值（包含录制前的既往拦截 + 镜头 1、2 现场新增的两笔共 1.50 USDC；数字会随历史变动，只报增量、不报总数）；下方「保护明细」表逐条：「若放行将损失 X USDC」绿字、「声明 vs 实际」两行地址（声明 `0x2222…`、实际标红 `0x9999…`）、报告哈希。
- **屏幕动线**：`/guardrail` → 侧栏「审计 · 本金保护」`/intercepts` → 鼠标划过「若放行将损失」列与「声明 / 实际」列 → 页底提示条：每次拦截生成彩排报告并写入**本地账本**（合约未部署，不说"锚定上链"）。
- **旁白**（字数≈96）：
  > 每一次拦截都沉淀成账。顶部是累计避免的损失，下面每一条都写明「若放行将损失多少」，并把声明地址和真实要打的地址并排留痕。彩排报告哈希用 keccak256 计算、落盘可查。我们如实说：这套哈希的合约锚定（StandInAnchor）源码和合约测试都已就绪，但**还没部署到测试网**，所以目前是链下账本记录，裁决可核验的部分是账本，不是链上。拦截不是界面特效，是有记录的。
- **要点**：**不得**声称裁决已锚定上链或可第三方链上核验——合约未部署。只说"哈希可计算、账本可核验"。

### 镜头 4 · 1:10–1:40（30s）为什么拦得住：声明意图 vs 实际 calldata 比对
- **画面**：切到 `/rehearsal`「彩排报告」，它显示**最近一次**运行的比对。承接镜头 2 末尾的「无限授权」拦截：上半区逐字段表（操作类型 / 代币合约 / 收款方 / 金额）里只有「金额」行箭头显 `≠`、带「无限授权」徽章；下半区「命中规则」逐条红边 `Infinite approval detected`、`Amount exceeds declared`；底部报告 ID + 报告哈希。
- **屏幕动线**：`/intercepts` → 侧栏「审计 · 彩排报告」`/rehearsal` → 从上往下扫比对表 → 停在「命中规则」红条 → 点报告哈希。（如需同框展示 `Recipient mismatch`，先回 `/guardrail` 补点一次「▶ 收款方篡改」再看本页。）
- **旁白**（字数≈118）：
  > 为什么拦得住？靠的不是模型自觉，是一段确定性的比对代码。Agent 先声明它要做什么，门禁再解析它真正要提交的 calldata，逐字段对齐：操作类型对不对、代币合约对不对、收款方对不对、金额有没有超出声明、有没有无限授权。任何一项不一致，命中规则就会把原因写清楚——这里是无限授权检测、金额超出声明。判定放行还是拦截，输出这份带哈希的报告。它不赌 Agent「这次没被骗」，它只认「说的和做的一不一样」。
- **要点**：这一镜是创新点核心，语速可稍稳，让「不靠模型自觉、只认字段一致性」这句听清。

### 镜头 5 · 1:40–2:05（25s）如实记亏（诚实性证据）
- **画面**：切到 `/opportunities`「机会与决策」。点某条数据类悬赏的「▶ 让它做」，触发 SOP 状态机做**真实数据验收**；随后刷出结果卡「验收未通过 · 成本沉没记亏」，结算净利为**红色负数**（如 `-0.25 USDC` 或 `-0.40 USDC`），「验收规则判定」清单里对应一条显红「未过」，原因写明「未超过阈值」或「价格已过期 N 秒 / 两源价差超过容忍带」。
- **屏幕动线**：`/rehearsal` → 侧栏「运行 · 机会与决策」`/opportunities` → 选一条悬赏点「▶ 让它做」→（真实采集期间用硬跳切，**不加速**）→ 结果卡出现红色负净利 + 验收清单红「未过」条。
- **旁白**（字数≈92）：
  > 收入不是写死的。Agent 花成本去做一单，成不成由真实数据验收说了算：新鲜度不超过 60 秒、两源价差在 50 个基点容忍带内。这单真实回放没达标——验收未通过，成本照扣，账本老老实实记一笔亏损，净利是红色的负数。我们不承诺赚钱，亏损单是它诚实的证据。
- **导演备注（如何稳定拍到真实亏损单，二选一）**：
  1. 优先跑「价差监测」悬赏（`bnty-seed-02`，成本 0.25）：真实 BTC 两源价差绝大多数时候远小于 50bps，窗口结束判定「未超过阈值」→ 自然「验收未通过 · 成本沉没记亏 -0.25 USDC」，是最常见、最稳的真实亏损单。
  2. 或跑「数据简报」悬赏（`bnty-seed-01/03`）：偶发真实价差越带或超时（PRD 实测记录显示 CoinGecko 同分钟漂移可越 50bps 带）→ 同样如实记亏。
  - 若当次恰好全通过，**不要伪造**：改拍清单中某条真实「未过」，或直接呈现「通过」并在旁白保留「不承诺赚钱」的口径，另择时机补拍亏损单。**绝不后期改数。**

### 镜头 6 · 2:05–2:28（23s）经营边界：止损在 Agent 之外强制
- **画面**：切到 `/wallet`「经营设置」。三块卡：经营本金（金库余额）、每日最多亏多少（单日止损线：净亏损≥预算 30% 停手到次日；连亏 3 单熔断；连亏 2 次仓位减半；健康度<0.6 不接单）、可做的生意类型 + 支出护栏白名单表。随后快速切回 `/`「今日账本」：顶部三数 收入 / 成本 / 净利，次行「门禁避免损失」，底部「诚实边界」条。
- **屏幕动线**：`/opportunities` → 侧栏「资产 · 经营设置」`/wallet` → 扫过「每日最多亏多少」→ 侧栏「运行 · 今日账本」`/` → 停在顶部三数与「亏损单如实显示」条。
- **旁白**（字数≈88）：
  > Agent 能花多少钱、能亏多少，不是它自己说了算。本金、每日亏损上限、连亏熔断、白名单，都在它之外强制执行：今天亏到预算的 30% 就自动停手到次日。回到首页，收入、成本、净利三个数都来自落盘账本，亏损单如实显示，门禁避免的损失单独列出。
- **要点**：强调「在 Agent 之外强制」——止损与门禁都不依赖模型自律。

### 镜头 7 · 2:28–2:52（24s）工程可信度（终端实拍，快切）

  4. 屏幕列出：合约源码 `contracts/src/`（StandInAnchor 锚定报告哈希、PaymentVault 托管本金）、合约测试 `forge test` 4 passed；数据源 CoinGecko / Coinbase / Hacker News；账本落盘带回滚。**不列合约地址，避免暗示已部署。**
- **旁白**（字数≈92）：
